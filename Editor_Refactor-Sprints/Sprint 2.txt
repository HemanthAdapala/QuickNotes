🚀 Sprint 2 — Cursor Engine

This sprint is about making the editor feel intelligent.

The user should never have to fight the cursor.

The cursor should always appear where the user expects it to be.

Think of the cursor as an invisible assistant that understands intent.

🎯 Goal

Transform the cursor from a simple blinking line into an intelligent insertion system that behaves naturally throughout the entire document.

The user should never think:

"Why did the cursor go there?"

Scope

Sprint 2 focuses exclusively on cursor placement and insertion behavior.

Do not implement:

Auto scrolling
Image layout improvements
Rich text improvements
Selection improvements
Animations

Those belong to later sprints.

Features
1. Intelligent Tap Placement

The cursor should always appear as close as possible to where the user taps.

Requirements:

Tap inside text → Cursor moves to nearest character.
Tap at end of line → Cursor moves to end of line.
Tap inside empty paragraph → Cursor appears immediately.
Rapid repeated taps should never confuse the editor.
Acceptance Criteria
Cursor placement feels predictable.
No unexpected jumps.
No snapping to incorrect positions.

Requirements:

4. Cursor Persistence

The cursor should remember its position.

Examples:

Rotate device.
Close and reopen keyboard.
Switch apps briefly.
Open formatting toolbar.

The cursor should remain exactly where the user left it.

5. Focus Management

Only one editing context should ever be active.

Requirements:

No duplicate cursors.
No focus loss.
No keyboard flicker.
Stable editing state.

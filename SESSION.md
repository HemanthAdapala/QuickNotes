# SESSION

## Current Goal

Implement the redesigned Folder and Category screens from Figma with maximum visual fidelity.

The Figma design is the source of truth.

The objective is to reproduce the design as accurately as possible while preserving existing functionality and navigation.

---

## Today's Goal

### Design Implementation

Goals:

* Implement the Folder screen exactly as defined in Figma.
* Implement the Category screen exactly as defined in Figma.
* Match layout, spacing, proportions, alignment, and visual hierarchy precisely.
* Preserve all existing functionality while updating the presentation layer.
* Reuse existing components where possible without affecting visual accuracy.
* Maintain consistency with the QuickNotes design language established on the Home Screen.

### Design Fidelity Requirements

* Follow Figma measurements as closely as possible.
* Match padding, margins, spacing, and component sizing.
* Match corner radius and card proportions.
* Match typography hierarchy and text placement.
* Match icon sizes and positioning.
* Match section spacing and content grouping.
* Preserve intentional whitespace and visual balance.
* Avoid Flutter default spacing if it differs from the design.

### Implementation Constraints

* Do NOT redesign any part of the screen.
* Do NOT simplify layouts.
* Do NOT add extra elements.
* Do NOT remove existing elements shown in Figma.
* Do NOT reinterpret the design.
* Treat the Figma file as the single source of truth.

### Validation

Before marking the task complete:

* Compare the implementation against the Figma design.
* Identify any remaining visual differences.
* Reduce those differences as much as possible.
* Ensure the final result feels visually indistinguishable from the reference.

* Folder screen matches the Figma design with high fidelity.
* Category screen matches the Figma design with high fidelity.

## Notes

Investigate the Figma design thoroughly before implementation.

Do not assume dimensions, spacing, or behavior.

If any part of the design is ambiguous, ask questions before coding.

Prioritize visual accuracy over convenience.

Prefer reusing existing components and design tokens where possible to maintain consistency and reduce future maintenance.
